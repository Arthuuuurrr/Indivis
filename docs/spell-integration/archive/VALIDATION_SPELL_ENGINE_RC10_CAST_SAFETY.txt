Observed problem
----------------
Finite casts, especially CHANNEL spells, could appear to channel forever and never settle into a completed cast. This was reported both with target-required spells and targetless AOE spells.

Root cause 1 — CHANNEL auto-restart
-----------------------------------
SpellHotbar passes keyHeld(option, STOP_released, START_released).
START is debounced after a successful start until physical key-up.
RC9 used STOP_released to restart CASTING/CHANNEL when the previous process was no longer active.
For CHANNEL, a finite completed process could therefore restart immediately while the same key press remained held.

RC10:
- CHANNEL restart uses START_released;
- non-CHANNEL CASTING preserves STOP_released;
- early key-up/cancel behavior remains unchanged.

Root cause 2 — cast duration safety
-----------------------------------
SpellParameters.hasteAffectedValue(base, haste) was a raw base / haste division.

RC10:
- non-finite haste -> neutral fallback;
- haste <= 0 -> neutral fallback;
- 0 < haste < 0.1 -> clamp 0.1;
- non-finite result -> neutral fallback;
- otherwise base / haste.

Spell Power HASTE is defined with default 100, minimum 10, maximum 1000, so normalized minimum is 0.1.
