Goal
----
First proportional pass for the 40-armor scale:
- modded armor points x2;
- vanilla armor unchanged;
- preserve old relative ranking between modded sets;
- do not touch toughness, max health, knockback resistance, spell power or other attributes.

Component rule
--------------
Only modifiers matching ALL conditions are scaled:
1. item registry namespace != minecraft;
2. attribute == generic ARMOR;
3. operation == ADD_VALUE;
4. slot == FEET, LEGS, CHEST, HEAD, ARMOR or BODY.

Therefore accessories/hand items using ANY/MAINHAND/OFFHAND are not accidentally doubled.
Multiplicative ARMOR modifiers are preserved unchanged.

ARMOR40 formula audit
---------------------
Previous HUD 1.3.2 ARMOR40 code only:
- raised the EntityAttribute clamp/max to 40;
- rendered a second armor HUD row.
It did NOT change DamageUtil's vanilla 20-point mitigation ceiling.

The balance module remaps DamageUtil.method_5496 to a true 0..40 scale:
- intermediate damage input x2;
- armor clamp 20 -> 40;
- mitigation divisor 25 -> 50;
- final damage result x0.5.

For an old modded armor value A and the new doubled value 2A, this is algebraically equivalent to the old protection curve, including toughness. It avoids flattening high-tier modded sets at the vanilla 20-point cap.
Vanilla armor values are intentionally not doubled and therefore occupy lower positions in the new 40-point progression.
