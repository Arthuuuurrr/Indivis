# Roadmap Indivis

> **Source de vérité : [Milestones GitHub](https://github.com/Arthuuuurrr/Indivis/milestones)**
>
> Le Project V2 `Indivis` est conservé uniquement à titre historique car son index d'items est incohérent.
> Le pilotage actif se fait avec les **Milestones + Issues + labels + assignees**, directement dans GitHub.
> L'Issue [#93 — ROADMAP — Indivis](https://github.com/Arthuuuurrr/Indivis/issues/93) reste ouverte comme point d'entrée transversal.

## Conventions de priorité

- `Priorité maximale -P1`
- `Problème prioritaire secondaire -P2`
- `A régler -P3`
- `A traiter -P4`

Le préfixe `P0` reste réservé aux urgences explicitement indiquées dans le titre.

## Phases

1. `0 — Validation technique`
2. `1 — Progression & combat`
3. `2 — Monde & biomes`
4. `3 — Quêtes & narration`
5. `4 — Donjons & boss`
6. `5 — Contenu bêta & finition`

Les échéances des milestones sont indicatives. Pour replanifier une tâche, modifier simplement son **Milestone** dans l'Issue.

## Règle de création et de mise à jour des Issues

Avant toute nouvelle issue :
1. rechercher les issues existantes avec plusieurs formulations pertinentes ;
2. mettre à jour / rouvrir l'issue existante si elle couvre déjà le sujet ;
3. créer un nouveau ticket uniquement en l'absence de correspondance réelle.

Chaque issue opérationnelle doit avoir :
- une priorité ;
- les labels de domaine pertinents ;
- un Milestone ;
- un assignee lorsqu'il est connu.

Le label `A tester / Valider` est réservé aux tâches pour lesquelles un **correctif candidat existe réellement** et attend un test. Il ne doit pas servir de statut générique pour une issue simplement signalée, en triage ou non traitée.

Voir `CONTRIBUTING.md` pour la convention complète.
